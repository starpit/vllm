## Goal

Ship `ferrite-model-qwen3-next` so `Qwen3NextForCausalLM` (e.g.
`Qwen/Qwen3-Next-80B-A3B-Instruct`) runs through the ferrite forward
path with parity vs Python vLLM. Hand-written
`vllm-cuda::model::qwen3_next` is the bottleneck oracle (the runtime
already has `GdnStatePool`, GDN kernels, GGUF loader, and is verified
correct per `c3fc87db2`).

## Architecture deltas vs already-supported arches

1. **Hybrid layers** — `linear_attention if (i+1) % 4 != 0 else full_attention`
   (`vllm/transformers_utils/configs/qwen3_next.py:251-255`).
   ~75% GDN, ~25% full-attn.
2. **GDN linear attention** — Gated Delta Net: `in_proj_qkvz` GEMM +
   `in_proj_ba` GEMM → split → causal_conv1d (state) → fused gating →
   recurrent (decode) / chunk (prefill) delta-rule → RMSNormGated → out_proj.
3. **Full attention with output gate** — `attn_output_gate=True`
   doubles Q heads; post-attn `* sigmoid(gate)` before `o_proj`
   (`vllm/model_executor/models/qwen3_next.py:917-942`).
4. **Per-head Q/K RMSNorm** — same pattern as Qwen3 / Qwen3-MoE.
5. **Partial RoPE** — `partial_rotary_factor=0.25` (only first 25% of
   head dims rotate).
6. **Shared-expert MoE** — same shape as Qwen3-MoE's
   `SharedFusedMoELayer` (sigmoid-gated shared + routed). Reusable.

## Non-goals (this plan)

- Quantized variants (FP8, GGUF-quant). Reuse the BF16 path landing
  pattern from Mixtral / Qwen3-MoE; quant peers are a follow-up.
- MTP (`qwen3_next_mtp.py`). Speculative decoding is out of scope.
- Any edit to `cuda_worker.rs` for arch-specific dispatch. The
  `GdnStatePool` is already constructed there for the hand-written
  path; ferrite consumes it via `ForwardCtx`, no new arch arms.
- Any edit to `vllm-cuda` model code. Hand-written stays as the
  oracle; ferrite is the new path.

  `fused_gdn_gating`, `causal_conv1d_update`, `causal_conv1d_prefill`,
  `fused_recurrent_gdn_fwd`, `gdn_qkvz_split_{bf16,f16,f32}`,
  `gdn_conv_output_split`, `gdn_rms_norm_gated`. Built by

- GGUF loader for Qwen3-Next (commit `f67072064`).
- `SharedFusedMoeRefImpl` + `SharedFusedMoELayer` (Qwen3-MoE, BF16).

## Phases (each lands as one wholesale commit; no piecemeal)

### Phase 1 — `OpKind::GdnAttention` plumbing

Add the IR node and total emission. Mirrors how `MlaAttention`
landed for DeepSeek-V2.

- `OpKind::GdnAttention` in `ferrite-forward-macro/src/classified.rs`,
  registered in `OpKind::from_name` for DSL `gdn_attention(...)`.
- `Instruction::GdnAttention` variant in `ferrite-forward/src/instr.rs`
  + `eval` arm that calls the kernels listed above.
- `FieldLoad::GdnAttention` codegen arm in
  `ferrite-forward-macro/src/emit.rs` matching the kernel-side loader's
  signature.
- A single `GdnAttentionRefImpl` (BF16, tp=1) gating on the
  presence of `linear_num_value_heads` in `ModelParams`. Loads
  `in_proj_qkvz`, `in_proj_ba`, `conv1d`, `dt_bias`, `A_log`, `norm`
  (RMSNormGated), `out_proj`. Mirrors `vllm-cuda` `GdnWeights::load`.
- `MatchContext`-driven dispatch (no panics, no rejections —
  `MEMORY: feedback_no_rejections_total_emission`).

### Phase 2 — `ForwardCtx` extension

One field, one call-site change. No new pool.

- Add `pub gdn_state: Option<&'a GdnStatePool>` to `ForwardCtx`
  (`ferrite-forward/src/lib.rs:206-223`). Re-export `GdnStatePool`
  from a place `ferrite-forward` can name (likely
  `ferrite-kernels::gdn_state` — move the struct out of
  `vllm_cuda::model::qwen3_next` if needed; keep the hand-written
  path as the consumer too, no behavior change).
- `cuda_worker` builds `ForwardCtx` with the existing `Option<GdnStatePool>`
  threaded in. Existing arches see `gdn_state: None`; no behavior change.

### Phase 3 — Full-attention output gate + partial RoPE

- Verify whether existing `RopeAppend` Impls already accept a partial
  factor. If not, add a `partial_rotary_factor` bound that the rope
  kernel reads (don't add a new OpKind unless math actually
  diverges; per `feedback_opkind_is_math_not_fusion` OpKind variants
  name math primitives).
- Output gate: simplest path is to expose the gated full-attention
  as `gated_attention(q, gate, k, v, ...)` — gate is the second half
  of a doubled-Q projection, `attn_output * sigmoid(gate)` epilog.
  If a single new OpKind is cleaner than DSL-level fusion of
  `attention(...)` + `* sigmoid(gate)`, add `OpKind::GatedAttention`.
  Decision goes in HANDOFF before code lands.

### Phase 4 — `SharedFusedMoeRefImpl::applies_to` disambiguation

Qwen3-MoE-Instruct and Qwen3-Next both expose `num_experts`; need
to gate Qwen3-Next out of the Qwen3-MoE Impl. Likely on presence of
`linear_num_value_heads` (Qwen3-Next-distinctive). Add a
`Qwen3NextSharedFusedMoeRefImpl` peer if behavior actually differs
(it shouldn't — the shared-expert math is identical), otherwise
just refine the existing Impl's `applies_to`.

### Phase 5 — `ferrite-model-qwen3-next` crate

The wholesale arch landing.

- New crate `vllm-rs/crates/ferrite-model-qwen3-next/` with `Cargo.toml`,
  `build.rs`, `configs/`, `src/lib.rs`. Workspace + `ferrite-models`
  registration with feature `arch-qwen3-next`.
- DSL body uses
  `if layer % full_attn_period == full_attn_remainder { … } else { … }`.
  `full_attn_period=4`, `full_attn_remainder=3` advertised through the
  per-arch `model.json` bound table (`ferrite-forward-macro::config`).
  Precedent: DeepSeek-V2 `if layer < first_k_dense_replace`
  (`ferrite-model-deepseek-v2/src/lib.rs:57-67`).
- `configs/` covers the published checkpoints (80B-A3B-Instruct,
  80B-A3B-Thinking) plus a `1-layer` smoke config.

### Phase 6 — Verification

Per `MEMORY: feedback_handoff_verified_means_inference` —
"verified" means a real inference run, not a tokenizer roundtrip.

- `cargo build -p ferrite-model-qwen3-next` (with `FERRITE_MODELS=qwen3-next`).
- `cargo build -p vllm-cli --features cuda --release`.
- `vllm chat` against the BF16 80B-A3B-Instruct checkpoint
  → coherent output (per `MEMORY: feedback_no_run_chat`,
  `timeout`-wrapped; loops on garbage, exits clean on coherent).
- Parity vs Python vLLM logits at decode step 0 for a fixed prompt
  (`tests/`-style golden, BF16, tp=1).

## Cross-cutting rules (drawn from MEMORY, load-bearing)

- **No cuda_worker arch arms** (`feedback_no_cuda_worker_edits`,
  `feedback_ferrite_owns_everything`).
- **No rejections / Err helpers** in emit/match
  (`feedback_no_rejections_total_emission`,
  `feedback_no_intentional_errors`,
  `feedback_no_unimplemented_singletons`,
  `feedback_no_panics_in_compiler`).
- **No piecemeal codegen migration** — each phase lands across all
  affected Impls in one commit (`feedback_no_piecemeal_codegen_migration`).
- **No special-case macros** (`feedback_no_special_case_macros`):
  extend `forward!` / OpKind, never bespoke proc-macros.
- **No new constants inline** — `linear_num_value_heads`, `head_v_dim`,
  partial-RoPE factor, conv-kernel size, GDN period/remainder are all
  named bounds (`feedback_no_hardwired_constants`).
- **Verify on the smallest coherent reference** (`feedback_smallest_model_for_verify`,
  `feedback_coherent_python_reference`).
- **Test-first for codegen changes** (`feedback_test_first_for_codegen`,
  `feedback_unit_tests_not_cargo_check`): every classified.rs / emit.rs
  change lands with a `codegen::tests` unit test before the
  production change.

## Fixed sequencing constraint

Phases run **strictly in order**. Phase 5 (the crate) cannot land
before Phase 1 (OpKind). Phase 4 (Moe disambiguation) must land
before or with Phase 5 to avoid the existing Qwen3-MoE Impl
silently claiming Qwen3-Next layers. Phase 6 verification gates
the merge.
